# Washington RV Scraper Diagnosis

Date: 2026-05-18

## Root Causes

1. The clearest source of the approximate 1,300-listing ceiling is `scraper-review.md`, FILE 6, `scripts/import-tinyfish.ts`.
   - `if (listings.length > 200) ... continue;` skips any run with more than 200 listings. Large dealers are treated as scraper errors.
   - `DEALER_INFO` is a hardcoded subset of domains, while `wa-dealers.json` contains the statewide dealer list.
   - `seenVins` is global across all dealers, so the same VIN observed through multiple runs/domains is collapsed before DB import.

2. Reolit/data loss between scrape and display is in the import/sync layer.
   - `scraper-review.md`, FILE 3, `syncScraperDataToDB`, silently skips records for `_removed_at`, invalid/unknown type, invalid price, missing make, missing year, JSON parse failures, and duplicate insert errors.
   - FILE 4, `upsertListing`, expects `record.type`, but the scraper-shaped records in the review use `rv_type` in several paths. Records pushed with `rv_type` only are skipped at `normalizeType(record.type)`.
   - FILE 3 and FILE 4 update existing listings only by VIN. VIN-less records depend on DB uniqueness behavior and can be skipped as duplicates without a useful reason count.

3. Deduplication does not match the required rule.
   - FILE 6 dedupes by VIN globally across all dealers.
   - FILE 3 and FILE 4 upsert by VIN globally in the listings table.
   - No reviewed code implements dealer-scoped dedupe only for Class C, fifth wheels, and travel trailers by `year + manufacturer + brand + model + floorplan`.
   - All other categories should retain every unit, but current VIN/global duplicate logic can collapse them.

4. Pagination and request completeness are not audited.
   - The reviewed code imports already-produced snapshots/runs and does not verify that all dealer pagination was followed.
   - The `>200` TinyFish guard is a hard loss point for high-volume dealers.
   - `wa-dealers.json` has repeated group inventory URLs, especially Poulsbo RV location rows pointing to the same `/rvs/` URL. The prior domain grouping made it hard to audit location-level inventory coverage.

5. Required-field handling is inconsistent.
   - Some import paths accept zero-photo rows; the new pipeline excludes zero-photo listings before sync.
   - Description/spec extraction was not centralized, so display-ready records were not guaranteed.

## Implemented Fix

The new Python package in `rv_inventory_scraper/` provides:

- Full pagination discovery with no listing-count cap.
- Detail-page extraction for title, price, photos, description, specs, VIN, stock number, year, manufacturer, brand, model, floorplan, and RV type.
- Mandatory photo filtering: zero-photo listings are excluded entirely.
- Business-rule dedupe only for Class C, fifth wheels, and travel trailers within one dealer.
- Unit-preserving identities for all other categories.
- Full sync behavior: insert new listings, update existing listings, and flag/delete missing listings as sold depending on available schema columns.
- Price-change tracking in `rv_price_changes`.
- Opt-in customer notification queueing in `rv_price_change_notifications`, sourced from `rv_price_alert_subscriptions`.
- Daily 3:00 AM APScheduler integration in `rv_inventory_scraper/scheduler.py`.

## Run Commands

Install dependencies:

```powershell
python -m pip install -r requirements.txt
```

Run a one-time scrape and DB sync:

```powershell
$env:DATABASE_URL="postgresql://user:pass@host:5432/db"
python -m rv_inventory_scraper.cli --dealers wa-dealers.json --output output/wa-rv-inventory.json
```

Run the daily 3:00 AM scheduler:

```powershell
$env:DATABASE_URL="postgresql://user:pass@host:5432/db"
python -m rv_inventory_scraper.scheduler
```
