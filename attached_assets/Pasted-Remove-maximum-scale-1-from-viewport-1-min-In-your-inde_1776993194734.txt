Day 2 — App Engine config (ship together in one deploy)
5. Fix compression + cache headers in app.yaml
Update your handlers so static assets get brotli/gzip and long cache times. Example:
yamlruntime: nodejs20

handlers:
  # Real static files served before SPA catch-all
  - url: /favicon.ico
    static_files: dist/favicon.ico
    upload: dist/favicon\.ico
    http_headers:
      Cache-Control: "public, max-age=86400"

  - url: /manifest.json
    static_files: dist/manifest.json
    upload: dist/manifest\.json
    http_headers:
      Cache-Control: "public, max-age=86400"

  - url: /robots.txt
    static_files: dist/robots.txt
    upload: dist/robots\.txt

  - url: /sitemap.xml
    static_files: dist/sitemap.xml
    upload: dist/sitemap\.xml

  # Hashed assets get forever cache
  - url: /assets/(.*)
    static_files: dist/assets/\1
    upload: dist/assets/.*
    http_headers:
      Cache-Control: "public, max-age=31536000, immutable"
      X-Content-Type-Options: "nosniff"

  # SPA catch-all — return HTML shell only for known app routes
  - url: /.*
    static_files: dist/index.html
    upload: dist/index\.html
If App Engine standard isn't compressing, the cheapest correct answer is to front the site with Cloudflare (free tier) — point DNS at Cloudflare, let them proxy to App Engine. They add brotli, CDN caching, and WAF for free.

Ship CSP in report-only mode first. Watch the violation reports for a week, then flip to enforcing.
7. Fix soft 404s
Your SPA catch-all currently returns HTTP 200 for everything. Add a real 404 handler. Two options:

Quick: In the React router, when matching the * fallback route, inject <meta name="prerender-status-code" content="404" /> and have prerender middleware read it. Without prerender middleware, Google will still index 404 pages as 200 — the only real fix is SSR/prerender (next step).
Proper: After step 8 below (prerender), the prerender layer sets HTTP 404 for unknown paths.

Days 3–5 — The fix that actually determines whether you rank
8. Ship SSG for static pages (2–3 days)
This is the one that matters. Install vite-plugin-ssg:
bashnpm i -D vite-ssg
Change entry point from main.tsx to use the plugin's bootstrap:
ts// src/main.tsx
import { ViteSSG } from 'vite-ssg'
import App from './App'
import { routes } from './router'

export const createApp = ViteSSG(App, { routes })
Update package.json:
json"scripts": {
  "build": "vite-ssg build"
}
In each page component, use useHead() from @vueuse/head (or react-helmet-async — you already have Helmet) to set title, description, canonical, OG tags, and JSON-LD. Now at build time, vite-ssg renders the full HTML for every route in your router and writes real HTML files. The result: each URL serves real content to crawlers, but still hydrates into your SPA for users.
Start with these routes (the ones with stable content):

/about, /contact, /sell, /dealers, /rv-dealers, /outfitter, /trips, /discover, /finance, /tow-guide

All 6 category landing pages

Leave /browse and individual listings as CSR for now — they're dynamic. For those, add a prerender service later (Prerender.io is $90/mo, or self-host Rendertron on App Engine for free).

Day 5–6 — SEO finishing
10. Add proper structured data (now that SSG renders it)

Homepage: Organization JSON-LD with name, logo, sameAs (social profiles), address, contactPoint.
Each /guides/* post: Article JSON-LD.
Each category page: ItemList pointing at listings.
Each individual listing (once built): Product with offers, brand, vehicleIdentificationNumber, mileageFromOdometer, images.
Everywhere: BreadcrumbList.

Use Google's Rich Results Test (search.google.com/test/rich-results) to validate each template.

Remove the <priority> field from every URL — Google ignores it. Remove the 6 duplicate /rv/* URLs you just 301'd. Submit the updated sitemap in Search Console.
