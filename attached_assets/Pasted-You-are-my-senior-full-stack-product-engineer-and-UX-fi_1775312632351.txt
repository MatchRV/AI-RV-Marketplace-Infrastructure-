You are my senior full-stack product engineer and UX fixer for **LotLink.io**, an RV marketplace web app built in Replit. Your job is to audit the existing codebase and implement every fix below—not mock them superficially. Prioritize working production behavior, clean UX, mobile responsiveness, and conversion-focused improvements. Do not ask for approval between issues unless you hit a true blocker. Then create a concise implementation plan grouped by the issues below, and execute each fix fully in order.

## Fix 1 — Listing detail pages (`/listing/:id`)

**Root cause investigation:** Determine whether the blank detail page is caused by bad route param handling, failed fetch, null listing data, hydration/render guard bug, permissions gating, missing fallback UI, schema mismatch between browse cards and detail page, or broken image array handling.

**Fix the route so every valid listing ID renders:**
- Hero image gallery
- Price, title, year/make/model/type
- Location, mileage or condition
- Deal score / market estimate if available
- Description
- Seller/dealer info
- CTAs: contact, save, share

**Add all missing states:**
- Loading skeleton
- "Listing not found" state for invalid IDs, with related inventory suggestions below
- Graceful fallback when photos are missing
- Graceful fallback when individual fields are null

**Also:**
- Generate per-listing SEO/social metadata if the framework supports it
- Add "Back to results" navigation from the detail page
- Confirm clicking any browse card opens a fully rendered detail page on both desktop and mobile

**Done when:** No valid listing renders blank. Invalid IDs show a helpful state. Detail page is visually complete and conversion-ready. Image gallery works on both viewports.

**Add to every browse card:**

**Performance requirements:** lazy loading, responsive image sizes, no layout shift.

**Done when:** Every browse card shows a real thumbnail or clean fallback. No broken image icons appear.

## Fix 4 — Discover uses real inventory (`/discover`)

**Connect Discover to the live listings dataset:**
- Build a swipe or next/previous card stack cycling through real listings
- Preserve match rationale tied to actual listing attributes (tags: off-grid, family, luxury, budget, towable, etc.)
- If user hasn't completed AI Outfitter, show lightweight starter preferences inline and let them continue
- Add actions: like/save, skip, view details, refine preferences
- Persist state in app memory or backend as appropriate
- When no matches remain: show refresh, broaden filters, and go-to-browse options

**Done when:** Discover serves multiple real listings in sequence. Match explanations reference actual listing attributes.

## Fix 7 — AI Outfitter onboarding progress UX (`/outfitter`)

**Audit the progress logic and replace with something intuitive:**
- Start at 0% before any input, or show "Step 1 of N" until sufficient data exists for a meaningful percentage
- Never show a discouraging low percentage (like 11%) as the starting state

**Structure the flow into clear stages:** budget → usage → size/sleeps → towability/drivability → camping style → optional preferences

**Add:**
- Immediate feedback after each step
- Completion reward messaging: improved matches, better Discover recommendations, dealer readiness, smarter filtering
- Consistent progress indicator across mobile and desktop

**Done when:** Progress starts logically. Users always know what comes next. Completion feels meaningful.

## Fix 8 — Mobile navigation and small-screen layout

**Implement a high-quality mobile nav pattern** (hamburger drawer or compact bottom nav):
- Primary destinations: Browse, Discover, Sell, Trips, Outfitter, account/profile
- Large tap targets

- No overlap with hero content, no clipped menu items

**Full mobile audit:** Review all primary routes at phone widths and fix overflow, broken grids, collapsed filters, and CTA issues.

**Done when:** Mobile nav is polished. No horizontal overflow on primary pages. Core flows are fully usable on phone-sized screens.
